# drone-photo-rectifier 사용설명서

이 문서 하나만 읽으면 프로그램 전체를 쓸 수 있게 쓴 설명서입니다.
프로그램 안에서는 **도움말 ▸ 사용설명서 (F1)** 로 언제든 볼 수 있습니다.

---

## 1. 이 프로그램은 무엇을 하나

드론으로 찍은 사진은 **자로 잴 수 없습니다.**

카메라가 지면과 완전히 수직이 아니고 렌즈에도 왜곡이 있어서, 사진 속 같은
길이여도 **위치마다 실제 길이가 다릅니다.** 사진 위쪽 10 px 가 현장에서 30 cm
인데 아래쪽 10 px 는 14 cm 인 식입니다.

이 프로그램은 현장에서 **줄자로 몇 군데만 재어 알려 주면**, 그 값들에 가장 잘
맞는 왜곡을 역으로 계산해서 사진을 폅니다. 결과물은 **어디를 재도 축척이 같은
사진**이고, 그대로 도면 바탕으로 쓸 수 있습니다.

```
      찍은 사진                              보정 결과
 +---------------------+                +---------------------+
 |  격자가 휘어 있고    |    실측값      |  격자가 곧고 직교    |
 |  위/아래 축척이 다름  |  ---------->  |  어디를 재도 같은    |
 |  (원근 + 렌즈왜곡)   |    조정계산    |  축척, 1 px = N mm  |
 +---------------------+                +---------------------+
```

### 할 수 있는 것

- 기울어 찍힌 사진을 바로 위에서 본 것처럼 펴기
- 렌즈 때문에 휜 직선을 곧게 펴기
- 결과물에서 임의의 거리 · 면적 재기
- CAD 도면(DXF), 축척이 살아 있는 이미지, 성과표로 내보내기
- **이 결과를 얼마나 믿을 수 있는지 숫자로 확인하기**

### 할 수 없는 것 (중요)

이 프로그램은 대상이 **하나의 평평한 지면 위에 있다**고 가정합니다.

- 건물 벽면 · 옥상 · 수목 · 적치물처럼 **높이가 있는 것은 보정 후에도
  제자리에 오지 않습니다.** (기복변위)
- 지형에 큰 경사나 단차가 있으면 구역을 나눠 따로 보정해야 합니다.
- 여러 장을 이어 붙인 정밀 3D 지형 모델이 필요하면 SfM 계열 도구가 맞습니다.
  이 프로그램은 **한 장의 사진을 도면 바탕으로 쓰는** 용도입니다.

## 2. 현장에서 미리 준비할 것

프로그램을 잘 쓰는 것보다 **현장에서 잘 재 오는 것**이 결과를 훨씬 크게
좌우합니다. 촬영 전에 이것만 챙기세요.

### 실측은 몇 개나?

| 실측 개수 | 무엇이 되나 |
| --- | --- |
| 5개 미만 | 계산이 되지 않습니다 |
| 5 ~ 8개 | 원근만 보정. 렌즈 왜곡은 못 잡습니다 |
| **9 ~ 11개** | 원근 + 렌즈 왜곡(k1). **권장 하한** |
| **12개 이상** | 렌즈 왜곡(k1, k2)까지. 검증도 충분 |

여유 있게 **12개 이상**을 권합니다. 몇 개는 일부러 계산에서 빼고 검산용으로
쓸 수 있습니다.

### 왜 긴 구간을 재야 하나

점 찍는 오차는 구간 길이와 **무관하게** 항상 몇 픽셀입니다. 반면 신호(구간
길이)는 길이에 비례합니다. 그래서 정보량이 **길이의 제곱**으로 늘어납니다.

| 실제 길이 | 정보량 |
| --- | --- |
| 0.85 m | 1배 |
| 2.6 m | 9배 |
| 11.5 m | **183배** |

0.85 m 짜리 네 개를 합쳐도 11.5 m 짜리 하나의 2 % 밖에 안 됩니다. 그러면서
오차는 고스란히 들어옵니다. **사진에서 100 px 미만으로 보이는 구간은 쓰지
마세요.** 측량에서 기준선을 길게 잡는 이유와 같습니다.

### 어디를 재야 하나

1. **사진 네 귀퉁이까지 고르게.** 한쪽에 몰리면 반대편 정확도가 급격히
   나빠집니다. 이게 가장 흔한 실패 원인입니다.
2. **방향을 섞어서.** 가로 방향만 재면 세로 축척이 제대로 결정되지 않습니다.
   가로 · 세로 · 대각을 섞으세요.
3. **길이를 섞어서.** 2 m 짜리와 30 m 짜리를 함께 넣으면 축척과 렌즈 왜곡이
   잘 분리됩니다.
4. **반드시 지면에서.** 연석 모서리, 맨홀 뚜껑, 페인트 선 끝, 바닥 타일
   모서리처럼 **사진에서 콕 집어 찍을 수 있는 지점**을 고르세요.
5. **높이가 있는 것은 피하세요.** 담장 위, 화단 턱, 적치물 모서리는 안 됩니다.

### 재는 요령

- 줄자를 팽팽하게, 지면을 따라서 잽니다.
- 잰 값과 **그 두 지점이 어디였는지**를 사진으로 함께 남겨 두세요.
  나중에 사진에서 그 지점을 못 찾으면 실측값이 무용지물입니다.
- 지점은 스프레이나 표적으로 표시해 두면 가장 좋습니다.

### 촬영 요령

- 가급적 **수직에 가깝게** 찍으세요. 많이 기울수록 먼 쪽 정확도가 나빠집니다.
- 대상이 사진 가운데에 오게 하세요. 가장자리는 렌즈 왜곡이 큽니다.
- 초점과 노출을 맞춰 **모서리가 뚜렷하게** 찍히도록 하세요.

## 3. 5분 따라하기

실제 사진이 없어도 됩니다. **정답을 알고 있는 연습용 사진**으로 전 과정을
그대로 해 볼 수 있습니다.

### 1) 프로그램 실행

저장소 폴더의 **`실행.bat` 을 더블클릭**하세요.

터미널을 쓰신다면 저장소 폴더에서:

```
PYTHONPATH=src python -m drone_photo_rectifier
```

PowerShell 이면 `$env:PYTHONPATH = "src"; python -m drone_photo_rectifier`.
`pip install -e .` 로 설치해 두었다면 그냥 `drone-photo-rectifier` 만 쳐도 됩니다.

> 패키지가 없다는 메시지가 나오면 `pip install -r requirements.txt` 를
> 한 번 실행하세요.

### 2) 연습용 예제 만들기

**파일 ▸ 검증용 합성 예제 만들기** 를 누르고 폴더를 고릅니다.
알려진 원근과 렌즈 왜곡을 넣은 가상의 "드론 사진"과, 점 · 실측값이 이미
채워진 프로젝트 파일이 만들어집니다.

### 3) 예제 열기

**파일 ▸ 프로젝트 열기** 로 방금 만든 `synthetic.drproj` 를 엽니다.
사진 위에 점 19개와 실측 선분들이 보입니다.

### 4) 보정 실행

**F5** 를 누르거나 왼쪽 [진행 안내]의 `보정 실행` 링크를 누릅니다.
오른쪽 [보정] 탭에 결과가 나옵니다. 맨 위 초록색 한 줄이 판정입니다.

```
✔ 보정 결과가 양호합니다.  현장 기준 오차 약 ±27 mm.
```

### 5) 결과 보기

[출력] 탭에서 **보정 결과 생성 / 미리보기** 를 누릅니다.
[보정 결과] 탭으로 넘어가면 펴진 사진이 보입니다.

휘어 있던 격자가 곧게 펴지고 직교하는지 확인하세요.
사진 위에서 두 점을 클릭하면 실제 거리가 나옵니다. 격자 한 칸이 정확히
5 m 로 나오면 성공입니다.

### 6) 내보내기

[출력] 탭에서 원하는 형식으로 저장합니다.

## 5. 작업 순서

### 1단계 — 사진 열기

**파일 ▸ 사진 열기 (Ctrl+O)**

JPG, PNG, TIFF 를 지원합니다. EXIF 에 초점거리가 있으면 읽어 두었다가
카메라 파라미터를 내보낼 때 씁니다.

### 2단계 — 실측 거리 입력 (핵심)

이 프로그램에서 가장 중요한 작업입니다.

1. 툴바의 **실측 거리 추가 (D)** 를 누릅니다.
2. 사진에서 **줄자를 댔던 첫 지점**을 클릭합니다.
3. **두 번째 지점**을 클릭합니다.
4. 뜨는 창에 **현장에서 잰 값을 미터로** 넣습니다. (12.34 m 이면 `12.34`)
5. σ(예상 오차)를 정합니다. **줄자 오차만이 아니라 점 찍는 오차까지** 포함한
   값이어야 합니다. 사진에서 짧게 보이는 구간일수록 크게 주세요.

   | 사진에서의 길이 | 권장 σ |
   | --- | --- |
   | 500 px 이상 | 0.01 ~ 0.02 |
   | 200 ~ 500 px | 0.03 |
   | 100 ~ 200 px | 0.05 |
   | 100 px 미만 | 쓰지 마세요 |
6. 확인을 누르면 **다음 실측을 이어서 입력**할 수 있습니다.
   그만하려면 `Esc`.

**점을 정확히 찍는 요령**

- 마우스 휠로 **충분히 확대**한 뒤 찍으세요.
- 커서 옆 **확대경**(8배)에 십자선이 보입니다. 그 십자선이 실제 찍히는 자리입니다.
- 근처에 뚜렷한 모서리가 있으면 **자동으로 달라붙습니다**(서브픽셀 스냅).
- 이미 찍은 점은 방향키로 미세이동할 수 있습니다.
  방향키 0.1 px, `Shift`+방향키 1 px, `Ctrl`+방향키 0.01 px.
- 잘못 찍었으면 **오른쪽 클릭**으로 직전 점 하나를 취소합니다.

### 3단계 — 기하 구속 추가 (선택이지만 강력)

줄자를 대지 않아도 **아는 사실**이 있습니다. 주차장 구획선이 서로 평행하다든지,
건물 모서리가 직각이라든지. 이것도 훌륭한 관측입니다.

[관측] 탭에서 **직각** 또는 **평행** 을 누르고 선분 두 개(점 4개)를 찍으세요.
공짜로 얻는 정보인데 해가 눈에 띄게 안정됩니다.

### 4단계 — 보정 실행

**F5** 또는 [보정] 탭의 **보정 실행**.

무엇을 바로잡을지는 [자동 선택]이 알아서 고릅니다. 실측 개수가 적은데
파라미터를 많이 풀면 **과적합**(그 실측만 잘 맞고 나머지는 엉망)이 생기기
때문에, 관측 수에 맞는 안전한 조합만 켭니다. **보통은 손대지 마세요.**

### 5단계 — 결과 확인

[보정] 탭 맨 위의 한 줄 판정을 봅니다.

| 표시 | 뜻 | 할 일 |
| --- | --- | --- |
| ✔ 초록 | 양호 | 다음 단계로 |
| ⚠ 주황 | 확인 필요 | 아래 [7. 결과 읽는 법] 참고 |
| ✖ 빨강 | 실패 | 점 위치와 실측값 단위를 확인 |

[관측] 탭에서 **빨간 줄**이 있으면 그 실측값에 오타가 있거나 점을 잘못 찍은
것입니다. 그 줄의 '점' 칸을 더블클릭하면 사진에서 그 위치로 이동합니다.

### 6단계 — 좌표축 정렬 (선택)

**보정 ▸ 좌표축 정렬**

결과 도면의 원점과 X축 방향을 정합니다. **정확도와는 무관하고**, 도면을
보기 좋게 돌려 놓는 기능입니다. 건물 정면을 가로로 눕히고 싶을 때 씁니다.

### 7단계 — 결과 만들고 내보내기

[출력] 탭에서 **보정 결과 생성 / 미리보기** 를 누르면 [보정 결과] 탭에
정사영상이 나옵니다.

**꼭 검산하세요.** 결과 위에서 두 점을 클릭해 거리를 재 보고, 실제로 아는
길이와 맞는지 확인하세요. 이때는 실측에 **쓰지 않은** 구간으로 확인하는 것이
가장 정직합니다.

### 실측하지 않은 것 재기

보정이 끝나면 정사영상 위에서 **아무거나 잴 수 있습니다.** 줄자를 대지 않은
것도요. 결과는 이렇게 나옵니다.

```
거리 14.130 ± 0.054 m   [모델 ±23 · 클릭 ±49 mm]
면적 142.27 ± 0.75 m²   [모델 ±0.46 · 클릭 ±0.59 m²]
```

`±` 뒤의 값이 그 측정을 얼마나 믿을 수 있는지입니다. 대괄호 안은 그것이
어디서 왔는지 나눠 본 것입니다.

| 몫 | 원인 | 줄이는 법 |
| --- | --- | --- |
| **모델** | 보정 파라미터가 완벽하지 않아서 | 실측을 더 넣는다 |
| **클릭** | 화면에서 점을 찍는 정밀도 | **원본 해상도 사진**을 쓴다 |

> **클릭 쪽이 더 크면 실측을 아무리 늘려도 나아지지 않습니다.** 그때는
> 사진 해상도가 병목입니다. 1280×720 에서 1 px = 34 mm 이던 것이
> 4000×3000 에서는 11 mm 가 됩니다.

여러 점을 이어 찍으면 꺾인 선의 전체 길이를, [결과에서 면적 측정]으로 바꾸면
다각형 면적을 잽니다.

**여전히 지면 위에 있는 것만 정확합니다.** 트럭 적재함 윗면, 컨테이너 상단,
적치물처럼 높이가 있는 것은 보정 후에도 제자리가 아니므로 재도 틀립니다.

### 메뉴

#### 파일

| 항목 | 설명 |

| 사진 열기 (Ctrl+O) | 보정할 사진을 불러옵니다 |

| 다른 이름으로 저장 (Ctrl+Shift+S) | |

| 종료 (Ctrl+Q) | |

> 프로젝트 파일은 **사진의 경로만** 저장합니다. 사진을 옮기거나 이름을

## 7. 관측 6가지 — 언제 무엇을 쓰나

| 종류 | 점 | 언제 쓰나 |
| --- | --- | --- |
| **실측 거리** ★ | 2 | 줄자로 실제로 잰 구간. **이것이 기본** |
| 평행 | 4 | 주차 구획선, 도로 양쪽 경계 등 실제로 나란한 두 선 |
| 직각 | 4 | 건물 모서리, 보도블럭 등 실제로 직교하는 두 선 |
| 등길이 | 4 | 길이는 모르지만 두 구간이 같다고 확신할 때 |
| 직선상 | 3 | 세 점이 실제로 한 직선 위에 있을 때 |
| 사잇각 | 3 | 세 점이 이루는 각도를 아는 경우(도 단위) |

**실측 거리만으로도 보정됩니다.** 나머지는 정확도를 올리는 보조 수단입니다.
다만 실측 거리가 **하나도 없으면 축척이 결정되지 않아** 계산이 되지 않습니다.

## 8. 결과 읽는 법

### 한 줄 판정

[보정] 탭 맨 위. 이것만 봐도 됩니다.

```
✔ 보정 결과가 양호합니다.  현장 기준 오차 약 ±27 mm.
```

여기서 `±27 mm` 는 **교차검증** 기준입니다. 관측을 하나씩 빼고 다시 계산해서
뺀 값을 얼마나 잘 맞히는지 본 것이라, 자기가 맞춘 잔차보다 정직합니다.

### 자세한 수치

| 지표 | 뜻 | 판단 기준 |
| --- | --- | --- |
| 관측 / 미지수 (자유도) | 잉여관측이 몇 개인가 | **자유도 3 이상** 확보 |
| σ₀ | 내가 준 σ가 현실적이었나 | 1 근처면 적정, 3 넘으면 문제 |
| 길이 잔차 RMS | 실측값과 평균 몇 mm 차이인가 | 작을수록 좋음 |
| 교차검증 RMS | 실용 정확도 | **이 값을 믿으세요** |
| 조건수 | 실측 배치가 고른가 | 크면 한쪽에 몰린 것 |

> **자유도가 0이면 잔차는 항상 0으로 나옵니다.** 잘 맞아서가 아니라
> 검증할 여유가 없어서입니다. 잔차가 작다고 좋은 것이 아니라,
> **잉여관측이 충분한데도** 작아야 좋은 것입니다.

### 판정이 주황(⚠)일 때

| 메시지 | 원인 | 해결 |
| --- | --- | --- |
| 조대오차 의심 N건 | 실측값 오타, 점 위치 실수 | [관측] 탭 빨간 줄 확인. 못 찾으면 [의심 관측 끄고 다시 계산] |
| 입력한 오차범위보다 많이 어긋남 | σ를 너무 작게 줬거나 지면이 평면이 아님 | 높이 있는 곳에서 잰 구간 제외 |
| 실측 배치가 치우침 | 한쪽에만 실측이 몰림 | 반대편 구석에 실측 추가 |
| 잉여관측 없음 | 실측이 미지수 수와 같음 | 실측 3~5개 추가 |

## 9. 정확도를 높이는 요령

1. **사진 네 귀퉁이까지 고르게 배치하세요.** 가장 효과가 큽니다.
2. **방향을 섞으세요.** 가로만 재면 세로 축척이 결정되지 않습니다.
3. **길이를 섞으세요.** 짧은 것과 긴 것을 함께.
4. **직각·평행 구속을 넣으세요.** 공짜인데 효과가 큽니다.
5. **점은 확대해서 찍으세요.** 확대경과 코너 스냅을 쓰세요.
6. **σ를 정직하게 주세요.** 대충 잰 것에 0.01 을 주면 그 값에 억지로
   맞추느라 전체가 나빠집니다.
7. **검산용 실측을 남겨 두세요.** 몇 개는 [사용] 체크를 풀고 계산한 뒤,
   그 구간을 결과에서 재 보면 실제 정확도를 알 수 있습니다.
8. **소실선(붉은 파선) 근처는 믿지 마세요.** 그 부근은 축척이 발산합니다.

## 10. 자주 겪는 문제

### "보정에 실패했습니다"

- 실측값의 **단위가 미터인지** 확인하세요. cm 로 넣으면 안 됩니다.
- 실측 거리가 **5개 이상**인지 확인하세요.
- 점을 엉뚱한 곳에 찍지 않았는지 확인하세요.
- 실측이 전부 **한 직선 위에** 있으면 풀리지 않습니다. 방향을 섞으세요.

### "보정 결과가 한 방향으로 찌부러졌습니다"

### "실측 배치가 부족해 해가 결정되지 않았습니다"

### "보정값이 물리적 한계까지 밀려났습니다"

셋 다 **같은 원인**입니다. 실측이 서로 비슷한 정보만 주고 있어서, 여러 개의
서로 다른 보정이 똑같이 잘 맞는 상태입니다. 프로그램은 그중 아무거나 고를
수밖에 없고, 그 결과가 현실과 동떨어집니다.

개수 문제가 아니라 **배치** 문제입니다. 실측을 10개 더 넣어도 전부 같은
방향이면 나아지지 않습니다.

| 이런 배치가 문제 | 이렇게 바꾸세요 |
| --- | --- |
| 전부 가로 방향 | 세로 · 대각 방향을 섞으세요 |
| 사진 한쪽에만 몰림 | 반대편 구석에도 넣으세요 |
| 길이가 다 비슷 | 짧은 것과 긴 것을 섞으세요 |
| 여러 구간이 거의 같은 선 위 | 서로 떨어진 위치에서 잡으세요 |

**가장 빠른 처방**은 [관측] 탭에서 **직각**과 **평행**을 몇 개 추가하는
것입니다. 줄자를 다시 대러 갈 필요가 없고, 세로 방향 정보를 바로 채워 줍니다.
주차 구획선, 보도블럭, 건물 모서리처럼 실제로 직교·평행인 곳이면 됩니다.

> 이 상태에서 GSD 를 바꾸는 것은 소용없습니다. 출력 설정이 아니라 보정
> 자체가 결정되지 않은 것이기 때문입니다.

### 잔차가 짧은 구간에서만 크게 나옴

같은 값(예: 0.85 m)으로 넣은 구간들이 결과에서는 0.47 m ~ 1.14 m 처럼 제각각
나온다면, **부호가 섞여 있는지** 보세요.

- **부호가 한쪽으로 몰림** → 모델 문제. 그 구역의 보정이 잘못 풀렸습니다.
- **부호가 섞임** → 구간마다의 문제. 줄자 값이 맞다면 **점이 잘못 찍힌 것**입니다.

짧은 구간에서 흔한 원인은 **가장자리 혼동**입니다. 페인트 선은 폭이 10~15 cm
라서, 바깥-바깥으로 재고 안쪽-안쪽을 클릭하면 그것만으로 0.2~0.3 m 가 어긋납니다.

### 결과 이미지가 이상하게 늘어남

소실선 근처까지 사진에 들어와서 그렇습니다. 카메라가 많이 기울어 찍힌
사진에서 생깁니다. 지평선 부근은 원래 보정할 수 없습니다.

### 결과 이미지가 너무 큼 / 만들다 멈춤

[출력] 탭에서 **GSD 값을 키우세요.** 20 mm/px 를 50 mm/px 로 바꾸면
용량이 약 1/6 로 줍니다. `출력 크기` 표시를 보면서 조절하세요.

### 잔차는 작은데 실제로 재 보면 안 맞음

- **자유도**를 확인하세요. 0이면 잔차는 항상 0입니다.
- **잉여도**가 0에 가까운 관측이 많으면 검증이 안 된 상태입니다.
- 실측이 한쪽에 몰려 있고, 안 맞는 곳이 반대편일 가능성이 큽니다.
- 재려는 대상이 **높이가 있는 것**은 아닌지 확인하세요.

### 점이 원하는 곳에 안 찍힘

- 더 확대하세요.
- **보기 ▸ 코너 서브픽셀 스냅**을 끄면 클릭한 자리에 정확히 찍힙니다.
- 찍은 뒤 방향키로 미세이동할 수 있습니다.

### 프로젝트를 열었더니 사진이 없다고 나옴

프로젝트 파일은 **사진의 경로만** 저장합니다. 사진을 옮겼거나 이름을 바꿨으면
다시 열어서 지정하세요.

### QGIS/CAD 에서 축척이 안 맞음

월드파일(`.pgw`)이 이미지와 **같은 폴더에 같은 이름으로** 있는지 확인하세요.
DXF 는 단위가 **미터**입니다. CAD 도면 단위를 미터로 맞추세요.

| σ (시그마) | 그 값이 대충 얼마나 틀릴 수 있는지 |
| 잔차 | 실측값과 계산값의 차이 |
| 자유도 | 관측 수 - 미지수 수. 0이면 검증 불가 |
| σ₀ | 내가 준 σ가 현실적이었는지 보는 값. 1 근처가 적정 |
| w | 그 관측이 유별나게 튀는 정도. 3.3 넘으면 의심 |
| 잉여도 | 그 관측이 다른 관측으로 검증되는 정도(0~1) |
| 교차검증 RMS | 관측을 하나씩 빼고 맞혀 본 정확도. 가장 정직한 값 |
| 조건수 | 실측 배치가 치우칠수록 커짐 |
| GSD | 결과 이미지 1픽셀이 현장에서 몇 mm 인지 |
| 소실선 | 축척이 무한대로 발산하는 경계. 붉은 파선으로 표시 |
| 월드파일 | 이미지의 축척·위치를 담은 작은 텍스트 파일(.pgw) |
| 좌표축 정렬 | 결과 도면의 원점과 X축 방향 정하기. 정확도와 무관 |
